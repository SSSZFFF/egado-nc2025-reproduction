## 0. 一句话结论

这是复旦大学 FiOWIN Lab 发表在 *Nature Communications* 上的 **EGADO（Edge-Guided Analog-and-Digital Optimization，边缘引导的模拟-数字联合优化）** 算法的公开配套代码，用于逆向设计**数字超材料（digital metamaterial）型硅光模分复用器**。

代码本身**逻辑完整、工程化程度较高**（三阶段流水线 + 断点续跑 + 批量 FDTD job），但**以公开仓库的形式无法直接跑通**：它依赖若干未随仓库发布的私有件（`setlogging`、扩展版 SPLayout 的 DBS）和作者本机的绝对路径。

本机（Windows / Python 3.12 / Lumerical 2025 R1 v251）实测：

| 阶段 | 能否跑通 | 卡点 |
|---|---|---|
| TO（拓扑优化） | ❌ | `import lumapi` 失败；`noise` 未装；`setlogging` 未定义 |
| ATD / EG-ATD（灰度→二值） | ❌ | 同上 + SPLayout 找不到 v251 + z 切片索引越界 |
| DBS（二值直接搜索） | ❌ | 同上 + 公开版 SPLayout 的 DBS 签名不兼容 |

好消息：**物理模型与算法内核是完整的**，缺的都是"胶水"层，全部可在半小时内补齐（见 §9）。

## 1. 项目背景

| 项 | 内容 |
|---|---|
| 名称 | EGADO — Edge-Guided Analog-and-Digital Optimization |
| 论文 | Sun, A., Xing, S., Deng, X. et al. *Edge-guided inverse design of digital metamaterial-based mode multiplexers for high-capacity multi-dimensional optical interconnect.* **Nat Commun 16, 2372 (2025)**. DOI: 10.1038/s41467-025-57689-7 |
| 单位 | 复旦大学 FiOWIN Lab |
| 联系 | alsun22@m.fudan.edu.cn |
| 许可证 | MIT License, Copyright (c) 2025 Bryvin Sal |
| 依赖 | Python 3.6（原 README）、`lumopt`、`lumapi`、`splayout`、Lumerical FDTD 2023R2.2 |
| 目标器件 | 5 模复用器（MUX）：5 路 TE₀ 输入 → 1 路多模波导输出（TE₀…TE₄） |

**算法要解决的问题**：拓扑优化（TO）得到的是**连续灰度**介电常数分布，物理上不可制造；直接二值化会严重恶化性能。EGADO 的思路是：

1. **TO** 先拿到高性能的连续结构；
2. **EG-ATD** 用 Canny 边缘检测找出"非黑非白"的**边缘像素**，其余像素直接按灰度二值化，只对边缘像素做逐像素 FDTD 决策（把 N 次仿真降到"边缘像素数"量级）；
3. **DBS** 在二值解上再做局部精修。

## 3. 三段式流水线全景

```
   阶段 1: TO (Topology Optimization)
   ─────────────────────────────────────────────
   base_TO.lsf  →  lumopt (adjoint)  →  L-BFGS-B, max_iter=400
   连续密度 ρ ∈ [0,1] → 过滤(240nm) → β 投影 → ε ∈ [ε_bg, ε_wg]
   产物: TO/x10000_y6000_f0240_m0000_<epoch>/parameters_<iter>.npz
         (含 params / eps / x / y / z / beta / eps_min / eps_max)
                    │
                    ▼
   阶段 2: EG-ATD  (Edge-Guided Analog-to-Digital)
   ─────────────────────────────────────────────
   func_get_conversion_matrix.get_conversion_matrix()
     eps → 归一化 → skimage.feature.canny → 边缘图 (300×500)
     → 最大值池化卷积(kernel=scale+buff, stride=scale) → 边缘标记 (50×83)
     → pattern_mapping: 非边缘像素取灰度中心值；边缘像素 = 0.5
     → 三分类: >0.99 直接"沉积(Si)" / <0.01 直接"刻蚀(孔)" / ≈0.5 待定
   逐像素 flip-pixel（每个 .fsp 一份，5 个模式并行 addjob/runjobs）
     cost = target_fom × N_mode − Σ T_i   (越小越好)
   产物: EGA2D/initial_DBS.npz, scan_order.npz, pattern conversion.png
                    │
                    ▼
   阶段 3: DBS (Direct Binary Search)
   ─────────────────────────────────────────────
   splayout.DirectBinarySearchAlgorithm：逐像素随机翻转，一轮 = 遍历全部像素
   产物: DBS/data/final_DBS.mat
```

**坐标/索引约定（最容易踩的坑，务必先读）**

| 量 | 约定 |
|---|---|
| `pixels_per_row` | `int(design_region_x / pitch)` = `int(10e-6/120e-9)` = **83**（沿 x） |
| `pixels_per_col` | `int(design_region_y / pitch)` = `int(6e-6/120e-9)` = **50**（沿 y） |
| 像素总数 | **4150** |
| 线性索引 n | `n = i*pixels_per_row + j`，i 沿 **−y**（从上往下），j 沿 **+x** |
| 像素中心 | `x = −design_region_x/2 + j*pitch + pitch/2`，`y = +design_region_y/2 − pitch/2 − i*pitch` |
| 状态语义 | **1 = 刻蚀**（材料 `n_bg`，即挖孔）；**0 = 沉积**（材料 `n_wg`，即硅） |
| 转换矩阵形状 | `(pixels_per_col, pixels_per_row) = (50, 83)`，**C-order** 展平 |
| `initial_DBS.npz` | `reshape(83,50)` 后 `ravel(order='F')` —— 这一步**是转置**，不是 bug |

> ⚠️ 最后一条我专门核对了 SPLayout 源码：`RectanglePixelsRegion.update()` 内部按
> `array[col, row]` 取像素（`pixelsregion.py:434-438`），即矩阵形状必须是 `(n_x, n_y)`。
> 所以 `reshape(pixels_per_row, pixels_per_col) + ravel(order='F')` 得到的是原矩阵的转置，
> **恰好**满足 SPLayout 的 `(n_x, n_y)` 约定。逻辑正确，但极其隐晦，建议加注释。

## 4. 物理模型详解（`base_*.lsf`）

### 4.1 参数注入机制

`.lsf` 里先写占位符，例如 `opt_size_x=none;`，Python 侧用字符串替换：

```python
# func_MDM_inverse_design.py:811-835
base_script = base_script.replace("opt_size_x=none", "opt_size_x={}".format(self.design_region_x))
...
base_script += 'setresource("FDTD","CPU",true);'
```

替换清单：`opt_size_x / opt_size_y / num_in_wg / num_out_wg / lam_c / out_wg_width / in_wg_width / wavelength_span / in_mode_list / out_mode_list / mode_num`。
**注意**：`z_min/z_max/pitch/radius` **不在**替换清单里，它们只在 Python 侧使用（`flipPixel` 直接 `addrect`）。

### 4.2 材料

```
n_wg = getindex('Si (Silicon) - Palik', c/lam_c);
n_bg = getindex('SiO2 (Glass) - Palik', c/lam_c);
self_define_materials = true;
```
自建两个 `Dielectric` 材料并改名为 `n_wg` / `n_bg`（单值折射率，无色散）。
好处：仿真快、与 Python 侧 `lumapi.getindex()` 取到的数值一致；坏处：**丢掉了材料色散**（40nm 带宽内影响很小）。
Python 侧 `MDM_InverseDesign.__init__`（L101-109）用 `lumapi.FDTD().getindex()` 取同一数值 —— 即**开一个 FDTD 会话只为查折射率**，且**从不 close**（见 §10-3）。

### 4.3 几何（已从 demo.fsp 二进制反解验证）

| 元素 | 参数 | 实测值 |
|---|---|---|
| 设计区 | `opt_size_x × opt_size_y` | **10 µm × 6 µm**，中心在原点 |
| FDTD 区 | `size_x = opt_size_x+1µm`, `size_y = opt_size_y+1µm` | 11 µm × 7 µm |
| 5 路输入波导 | x ∈ [−11, −5] µm，宽 0.5 µm | y 中心 = **+2.75, +1.375, 0, −1.375, −2.75 µm** |
| 1 路输出波导 | x ∈ [5, 11] µm，宽 2.5 µm | y ∈ **[0.5, 3.0] µm**（中心 1.75 µm） |
| 像素 | 120 nm × 120 nm，z ∈ [−110, +110] nm | demo.fsp 内 **4150 个 `pixel<n>` 对象**（id 0…4149） |
| 监视面 | x = 5.3125 µm（Lumerical 对齐网格，标称 5.3 µm），y ∈ [0, 3.5] µm，z ∈ [−1, 1] µm | h5 实测一致 |

> ⚠️ **输出波导不在设计区中心**：设计区 y ∈ [−3, 3]，但输出波导只占上半部分 y ∈ [0.5, 3.0]。
> 也就是说底部两路输入（−1.375、−2.75）必须"往上折"才能进入输出波导。
> 这是代码里的既定事实（`set('y',0.5*opt_size_y-0.5*out_wg_width)`），
> 但看起来不像常规 MUX 布局，**建议与论文图 1 核对是否本意**。

输入波导位置公式在两套脚本里**不一致**（重要，见 §10-12）：

```
base_TO.lsf / base_EGA2D.lsf（新式，demo 用的就是这个）:
  y_i = opt_size_y/2 − 0.5·in_wg_width − (i−1)/(num_in_wg−1)·(opt_size_y − in_wg_width)
      → 2.75, 1.375, 0, −1.375, −2.75   （覆盖整个 6 µm 高度，关于 y=0 对称）

base_A2D.lsf / base_DBS.lsf（旧式）:
  y_i = opt_size_y/2 − 0.5·(1/num_in_wg)·opt_size_y − (i−1)/num_in_wg·opt_size_y
      → 2.4, 1.2, 0, −1.2, −2.4        （间距 1.2 µm）
```

### 4.4 光源与监视器

- **光源**：`addmode`，`mode selection = user select`，`selected mode number = in_mode_list(i)`。
  demo 中 5 个 `Source_TE_mode{1..5}_1550` 都存在，x = −5.3 µm，y span = 1.5 µm。
- **监视器**：
  - `fom{i}`：2D X-normal power monitor
  - `fom{i}_mode_exp`：mode expansion monitor，`selected mode numbers = out_mode_list(i)`
    → 5 个监视器**位置完全相同**，各自测输出波导中的一个模式（TE₁…TE₅ 的 Lumerical 编号 = 物理 TE₀…TE₄）
- 每个输入模式对应一个 `.fsp` 文件（`TE_mode_{i}_EGA2D.fsp`），脚本里用
  `for (i=1:mode_num){setnamed("Source_TE_mode"+..., "enabled", (i==current_source));}` 只开一路源。

### 4.5 网格与边界

| 项 | base_TO.lsf | base_A2D / base_DBS.lsf | base_EGA2D.lsf |

| 全局 mesh accuracy | 3 | 3 | 3 |
| 设计区 override mesh | dx=dy=**30 nm**, dz=22 nm | dx=dy=**25 nm** | dx=dy=**30 nm**, dz=22 nm |
| 输出面附加 mesh | `fom_mesh` dx=20 nm | 无 | 无 |
| z 边界 | `z min bc = Symmetric`, `force symmetric z mesh` | 同 | 同 |

**z 方向只有 3 个采样点**：`z_points = int(220/110)+1 = 3`，对应 z = −110, 0, +110 nm。

## 5. EG-ATD 算法内核（论文的核心贡献）

`func_get_conversion_matrix.get_conversion_matrix()` + `MDM_InverseDesign.EG_ATDO()`

### 5.1 生成"边缘决策矩阵"

```python
analog_pattern = full_eps[:, :, 6]          # 取 z 方向第 7 层切片  ← 见 §10-1，索引可疑
analog_pattern = analog_pattern.T[:-1, :-1] # (300, 500)，单位 20 nm
analog_pattern = -np.flip(analog_pattern, axis=0)   # y 轴翻转到与像素索引一致
analog_pattern = (analog_pattern - min) / (max - min)   # 归一化到 [0,1]

edge_img = feature.canny(analog_pattern)    # Canny 边缘

scale = int(ceil(pixel_size_nm) / mesh_size)     # = 6  (120/20)
decision_area = scale + buff                     # buff = 0,2,4...
conv_result = convol(edge_img, decision_area, scale, buff//2)   # 最大值池化，输出 (50, 83)
mapped_result = pattern_mapping(analog_pattern, conv_result, 0.5, scale)
```

`convol()` 不是普通卷积，而是 **"窗口内是否存在边缘"的二值池化**（`int(np.sum(window*kernel) > 0)`），
输出尺寸 `((300−6)/6)+1 = 50`、`((500−6)/6)+1 = 83`，**正好等于像素阵列尺寸**。
它同时打印 **Direct Conversion Rate**（可以直接二值化的像素占比），`buff` 越大该比例越低。

`pattern_mapping()`：非边缘像素取对应 6×6 网格的中心灰度值；边缘像素统一置 **0.5**。

### 5.2 三分类 + 逐像素决策

```python
for row_idx, row in enumerate(conversion_matrix):
    for col_idx, col in enumerate(row):
        if 0.49 < col < 0.51: edge.append(...)      # 待定：边缘像素
        if col > 0.99:        etch_convert.append(...)     # 直接挖孔
        if col < 0.01:        deposit_convert.append(...)  # 直接填硅
```

然后对**只对 edge 列表**做扫描（`scan_order` 支持 `row_by_row` / `col_by_col`）：

```
对每个待定像素 n:
  1) 先把像素 n 置为"刻蚀"(状态1) → 跑一次 FDTD → etch = [T1..T5]
  2) 再把像素 n 置为"沉积"(状态0) → 跑一次 FDTD → deposit = [T1..T5]
  3) cost = target_fom × N_mode − Σ T_i
     取 cost 更小者，把像素固定下来
```

- 每次决策 **2 次 FDTD**（5 个模式并行），而不是全阵列扫描，这就是 EG-ATD 相对 DBS 的加速来源。
- 断点续跑：每步写 `A2D_states.npz`（`iterations` / `order` / `A2D_pixel_array`）。
- **防崩溃重启**：每轮迭代关闭并重新打开 `.fsp`（Lumerical 长时间跑会卡死），代码里有 `reopen_flag` 逻辑。
- 结束后 `move_files_to(.../data)` 并把目录重命名为 `data_epoch_<epoch>`。

### 5.3 代价函数

```python
def cost_function(self, filename):
    for i in range(len(filename)):
        self.fdtd[i].fdtd.eval('save("%s");' % filename[i])
        self.fdtd[0].fdtd.eval('addjob("%s");' % filename[i])   # 把 5 个仿真丢进同一个 GUI 的 job 队列
    self.fdtd[0].fdtd.eval('runjobs;')                          # 并行跑
    for i in range(len(filename)):
        self.fdtd[i].fdtd.eval('load("%s");' % filename[i])
    return [np.mean(fdtd.get_mode_transmission(f"fom{i+1}_mode_exp")[0,1,:])
            for i, fdtd in enumerate(self.fdtd)]
```

`get_mode_transmission()` 返回 `(模式数, 2, 频率点数)`，`[0,1,:]` = 第 0 个模式的透射谱，
再对 11 个频率点取平均 → 得到单值 FoM。

### 6.4 `full_pixel_array.npz`（28.4 KB）

**这是什么**：不是性能结果，而是**最终的二值像素图案（即器件版图几何）**。

换言之：**这是"优化收敛后的数字超材料版图"，里面没有 FoM、没有透射率、没有波长轴。**

| 长度 | 3600（float64） |
| 取值 | 只有 `{0.0, 1.0}`（已经是纯二值，说明 0.99/0.01 吸附那一步已完成或不需要） |
| `0` = 沉积 | 2146 个（59.6%），材料 `n_wg`（硅） |
| `1` = 刻蚀 | 1454 个（40.4%），材料 `n_bg`（孔） |

**形状：60 × 60**，三重判据一致（详见 §10 验证表）：
- 相邻像素跳变数 60×60 = **1182**，次优 2D 读法 ≥ 2078
- 周长/面积比 60×60 = **0.658**，其它读法 ≥ 0.86
- 最大连通域占比 60×60 = **29.8%**（最高）
- 算术自洽：`scale = 100/20 = 5`，`(300−5)/5+1 = 60` 恰好成立

→ 正方形设计区。最可能是 **6 µm × 6 µm @ 100 nm 像素**
（另一组数值等价解是 7.2 µm × 7.2 µm @ 120 nm —— 整个版图按比例缩放，单凭图案无法区分；
取 100 nm 是因为 `appendix_get_pixel_pattern.lsf:12` 用的就是 `pixel_size = 100*nm`）。

**器件识别（按端口反推）**

把数组按转换矩阵的自然顺序 reshape 成 `(row = y, col = x)`（值 0 = 硅画成白）后，
量左侧边界（x = 0…3 列）的硅条带：

```
rows  5- 9   y = +2.25 um   宽 0.50 um   ← 端口
rows 19-24   y = +0.80 um   宽 0.60 um   ← 端口
rows 34-38   y = -0.65 um   宽 0.50 um   ← 端口
rows 49-53   y = -2.15 um   宽 0.50 um   ← 端口
（另有 y=-0.15/-1.65 um 处 1-3 px 的孤立碎块，是 EG-ATD 逐像素决策留下的伪影，不是端口）
```

四个 0.5 µm 宽、间距 1.5 µm、关于 y = 0 对称的端口 —— 这正好是
**`num_in_wg = 4` + `base_A2D.lsf` 的"旧式"公式**：

```
y_i = opt_size_y/2 − 0.5·(1/num_in_wg)·opt_size_y − (i−1)/num_in_wg·opt_size_y
    = 3 − 0.75 − 1.5(i−1) = +2.25, +0.75, −0.75, −2.25   ✓ 完全命中
```

我对 16 组假设（两套公式 × num_in_wg ∈ {2,3,4,5} × 两种尺寸）做了 IoU 打分：

| 假设 | IoU |
|---|---|
| **旧式公式, num_in_wg = 4** | **0.667** ← 最优 |
| 旧式, nw = 3 | 0.265 |
| 旧式, nw = 5 | 0.220 |
| 新式, nw = 4 | 0.154 |

右侧边界（x = 57…59）只有一条宽带：**y = +2.00 µm，宽 1.8–2.0 µm** →
对应 `set('y', 0.5*opt_size_y − 0.5*out_wg_width)`，即 **out_wg_width ≈ 2.0 µm 的单根多模输出**。

**结论：这是一个 4 模（解）复用器**——4 路 0.5 µm 单模波导输入 → 1 根约 2 µm 宽的多模波导输出
（模式数大致与波导宽度成正比：论文的 5 模器件用 2.5 µm 输出，2.0 µm 外推约 4 个 TE 模，
与 4 路输入自洽）。行 5-8 是横贯全宽 100% 硅的实心带（y ≈ +2.15…+2.45 µm），
说明最上面那路输入是"直通"进多模输出、承担 TE₀ 的；
其余三路（+0.75 / −0.75 / −2.25 µm）通过下方结构向上汇聚，完成 TE₁…TE₃ 的模式转换。

**与论文对照（已核对 PMC 全文，PMCID PMC11894115）**

论文共 5 个数字超材料器件，**全部是 120 nm 像素**，均为"N 路 500 nm 单模输入 + 1 路多模输出"：

| 器件 | 输入/输出 | 设计区 | 像素数（按 120 nm 推算） |
|---|---|---|---|
| 2 模 MUX（仅仿真） | 2 / 1（900 nm），间距 1.3 µm | 3.6 × 3.6 µm² | 30×30 = 900 |
| **4 模 MUX（已流片）** | **4 / 1（1.8 µm），间距 1 µm** | **6 × 6 µm²** | 50×50 = 2500 |
| 5 模 MUX（已封装） | 5 / 1（3 µm） | 10 × 6 µm² | 83×50 = **4150** ← demo.fsp |
| 6 模 MUX | 6 / 1（3 µm），间距 1 µm | 10 × 8 µm² | 83×66 = 5478 |
| 双偏振 5 模 MUX（仅仿真） | 5 / 1（1800 nm） | 8 × 6 µm² | 66×50 = 3300 |

对照结果：

- 本文件的 **3600 像素不等于论文任何一个器件**（论文也从未给出像素总数）。
- 但本文件的 **设计区 6×6 µm、输入宽 0.5 µm、输出宽 1.8 µm 三项全部与论文的 4 模 MUX 精确吻合**，
  且 5 px × 100 nm = 500 nm、18 px × 100 nm = 1800 nm 都**整除命中**；
  若按 120 nm 读，则输入会变成 600 nm、输出 2160 nm，与论文不符。
  → 因此**像素节距应为 100 nm**（论文表格里的 120 nm 是最小特征尺寸 MFS，两者在本代码里是分开的参数：
  `pitch` 决定像素数，`rect_size` 决定 `scale`，`min_feature_size` 才是 MFS 约束）。
- 唯一不一致的是**输入间距**：本文件实测 **15 px 的自相关主峰 → 1.5 µm**
  （正是 `base_A2D.lsf` 旧式公式 + `num_in_wg=4` 的理论值 `opt_size_y/4 = 1.5 µm`），
  而论文流片版是 **1 µm**。

**最终判断**：这是论文**4 模 MUX 的一个设计迭代版本** —— 设计区、输入/输出波导宽度都对得上，
但用的是 100 nm 像素与 1.5 µm 输入间距；流片版后来改成了 120 nm 像素 / 1 µm 间距。
它不是 demo 里那个 5 模器件，也不是论文最终报告的那一版 4 模器件。

图形见 [analysis/pixel_pattern_60x60.png](analysis/pixel_pattern_60x60.png)（白 = 硅，黑 = 孔，并标注了端口位置与公式对比）。

### 8.2 TO 阶段的实测开销（重要）

飞检与冒烟测试（`analysis/preflight_to.py`、`analysis/run_to.py`）给出的硬数据：

| 项 | 实测值 |
|---|---|
| 求解器 | ✅ GPU（`fdtd-engine-msmpi.exe -gpu`，RTX 4060 Ti），2489 Mnodes/s |
| FDTD 网格 | **553 × 336 × 23** = 4.27 M 网格点 |
| 单次 FDTD 求解 | **≈ 100 s**（纯求解 100.8 s，另加 ~4 s 落盘） |
| 每次 FOM 评估 | 5 个模式 × (正向 + 伴随) = **10 次求解 ≈ 17 min** |
| 单次迭代 | ≈ 17–18 min |
| **`max_iter=400` 全量 TO** | **≈ 113 小时 ≈ 4.7 天**（已实测：第 0 轮含初始化共 41 min，之后每轮 ≈ 20–25 min） |
| 磁盘 | 稳定 ≈ 6.3 GB（`store_all_simulations=False` → 文件名固定为 `forward_0`/`adjoint_0`，每轮覆盖；G 盘余 2.1 TB，安全） |

> 实测日志里能看到 lumopt 会打印 `Running forward solves in threads` /
> `Running adjoint solves in parallel`，但本机只有**一块 GPU**，5 个 FDTD 求解在 GPU 上时间片轮转，
> 实际并不会加速（正向 5 个仍耗时约 14 分钟）。**不要指望线程并行能缩短总时长。**

几个关键结论：

1. **GPU 是必须的**。同一建模在 CPU 上单次要 381 s（≈11 倍慢），全量 TO 会变成 17 天。
   本机 `%APPDATA%\Lumerical\FDTD Solutions.ini` 里 `FDTD\GPU-mode=true`、
   资源配置 `device type = 'GPU'`，Python API 会话会自动沿用。
2. **`filter_R=240e-9` 实际写成 `f0239`**：`int(240e-9*1e9)` 因浮点表示截断成 239。
   这不是本次引入的——作者 `main.py` 里的原路径就是 `x10000_y6000_f0239_m0000_2`，说明作者也是这个行为。
3. **`base_TO.lsf` 里没有设计区 mesh override**（`base_EGA2D.lsf` 有 30 nm），所以 TO 用的是
   自动细化后的 ~20 nm 网格；若加上 30 nm override 可望快 ~2 倍，但会改变优化的数值结果，
   **我没有擅自改**。
4. lumopt 会打印 `Simulation file has 5 sources ... one forward simulation is not possible`：
   这是**性能提示不是错误**——`optimization.py:714` 有 `deactivate_all_sources()`，
   每个子优化只会打开自己那一路源，物理是正确的；代价是每个模式各跑一次正向仿真
   （10 次而不是 6 次）。
5. 每一轮迭代都会落一个 `parameters_<iter>.npz`，所以**随时可以中断**并用已有结果继续 EG-ATD。
   已核实：`optimization.py:341-345` 在 scipy 的每轮迭代回调里写
   `parameters_{iteration}.npz` 并**追加**一行 `convergence_report.txt`；
   `scipy.optimize.minimize(callback=...)` 每轮触发一次。

### 8.3 暂停与续跑（已实现）

TO 是长任务（本机 ~12–13 min/轮），随时可以安全中断：

```powershell
# 暂停：直接杀掉作业即可（-- 已实测，子进程 fdtd-engine 会被一起回收，不留残留）
job_kill <job_id>

# 续跑：从任意一个检查点接着跑
cd EGADO-main
python ..\analysis\run_to.py 5 1 --resume TO\x10000_y6000_f0239_m0000_0\parameters_69.npz
```

要点：

- **每个 `parameters_<n>.npz` 只有 2.3 MB**（70 个检查点合计 162 MB），里面含
  `params`（(501,301) 灰度图案）、**`beta`**（二值化进度）、`eps`、网格坐标。
  磁盘占用的 10 GB 几乎全在 `opts_0..4/` 的 `.fsp`/`.h5` 临时文件里，**可以删**，
  不影响续跑（续跑会新建工作目录）。
- 续跑会**新建一个工作目录**（lumopt 的 `prepare_working_dir()` 自动把后缀 +1），
  所以新目录里的 `parameters_*.npz` 又从 0 开始编号 —— **EG-ATD 阶段要指向新目录**。
- 续跑恢复的是 `params` + `beta`，**不恢复 L-BFGS-B 的内部历史**（Hessian 近似），
  会当作一次新的 L-BFGS-B 从检查点出发。因为已经接近局部极小，重新收敛很快。
- lumopt 的两段式流程：stage 1（β=1，连续优化）跑完 → `=== Starting Binarization Phase ===`
  → 每轮 β×1.2、跑 `continuation_max_iter=40` 次迭代，直到
  `discreteness = 1 − mean(4ρ(1−ρ)) > 0.99`。**EG-ATD 需要的是二值化之后的检查点**，
  所以 `--resume` 时会从检查点里把 β 一起恢复，延续原来的进度。

本次中断时的实测状态（`parameters_69.npz`）：

```

二值化  : 第 3 轮，beta = 1.728，discreteness = 0.6255，灰色像素 59.0%
连续域性能 : ΣT = 4.9381 / 5.0（单模 T = 0.996/0.990/0.987/0.984/0.981）
```

## 12. 一句话总结给作者

> 仓库把**算法主干**开源得很完整（TO → EG-ATD → DBS 三段 + 断点续跑 + 并行 job 调度），
