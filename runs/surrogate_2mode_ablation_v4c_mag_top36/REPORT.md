# 2-mode v4c — magnitude top-36 + 6D physics residual + refresh

Run: `F:\codex_project\inverse_design_sun\runs\surrogate_2mode_ablation_v4c_mag_top36`

## 设置

- `--mag-top-n 36`：每轮 DRC 后按 `abs(linear_prior)` 保留前 36 个核心候选
- `--top-k 1`，`--max-rounds 120`，`--max-fdtd 100`
- `--enable-refresh`；刷新硬门控 `last_refresh_flip_count`，无新 accepted flip 不刷新
- 6D 物理特征 Ridge；EI tie-breaker 改为 `1e-6 * abs(prior)`
- 远程无 torch，`compact_features=true`

## 结论

- `mag_top_n=36` 确实把 5 个核心像素都包进了候选池，但“进入池子”不等于“按正确顺序探索”：`(23,21)` 在第 6 轮被当成高幅值核心试了一次，初始态真实 `−0.005726`，随后被 tabu 锁住；后续即使状态变了，也没有再被重新探索。
- `(15,12)`、`(20,13)`、`(16,15)` 实际没有进入 Top-1 评估；说明只按 `abs(prior)` 过滤，仍然会被 DRC、tabu、邻域约束和 EI/Ridge 排序挤出。
- 结果最终 0.859395，低于 v3b/v3c，更远低于 baseline 0.886449。
- 物理解释仍然成立：`|prior|` 能圈出核心区，但**核心像素的增益是强状态依赖的**；初始态试 `(23,21)` 只会得到负增益。下一步不能再把“初始态幅值排名”当作直接执行顺序，必须做**状态感知的候选重排/回溯**：允许关键像素在刷新或状态变化后解除 tabu 重试，或显式构造“接近 baseline 关键状态”的课程式探索。

## 下一步建议

- 保留 `mag_top_n` 作为候选池，但把 `tabu` 对高幅值核心像素改成“软禁忌/延迟重试”，尤其在每次有效 refresh 后重新对全部 top-N 做一次 `abs(prior)` 排序。
- 增加 `patience_rounds` 或在无接受时强制继续扫描 top-N，避免 81 轮就停止。
- 对 `(23,21)` 单独做状态扫描：用 baseline `sweep2 step76` 的中间态作为起点附近的状态，验证 `(23,21)` 在该状态的 prior 和真实 `dJ`；目前已知中间态 prior 仍负但 `|prior|` 14/108，说明需要“延迟执行”而不是“初始执行”。
